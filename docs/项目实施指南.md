# 脑纹识别项目竞赛实施指南

## 0. 结论先行

这项比赛不要一上来复现 BrainprintNet。BrainprintNet 是论文工程，适合作为中后期的创新基线和对照模型；第二个仓库更适合作为“快速看到效果”的入门样例和演示界面参考。

建议主线：

1. 先用 PhysioNet EEG Motor Movement/Imagery Dataset 跑通单个受试者的数据读取、预处理和可视化。
2. 用 10 个受试者做经典机器学习基线，确认数据切分和评价流程没有错误。
3. 用 EEGNet 完成 109 人闭集身份分类。
4. 把任务从“分类”升级为“注册 + 验证”的开集身份认证，报告 EER、FAR、FRR、ROC-AUC。
5. 再做跨会话、跨任务实验，接入 BrainprintNet，比较 EEGNet、BrainprintNet 和经典特征方法。
6. 最后再做网页演示、模型压缩、可视化和比赛报告。

如果只有 3 至 4 周，建议直接砍掉第 5 步的大部分内容，以“可复现的 EEGNet + 严格开集认证 + 完整误差分析”作为交付，不要为了追求一个很高的分类准确率而牺牲切分可信度。

当前检测到本机为 Apple M1、8 GB 内存、约 19 GB 可用磁盘。建议在这台 Mac 上写代码、看数据和小规模调试，把 2 GB 原始数据集、预处理缓存和模型训练放到外接硬盘或带 NVIDIA GPU 的 Linux/云服务器上。BrainprintNet 仓库只优先使用 CUDA 或 CPU，不会自动使用 Apple MPS。

## 1. 先把题目定义清楚

“脑纹识别”至少有四种不同任务，指标和切分方式完全不同。

| 任务 | 问题 | 训练/测试要求 | 主要指标 |
|---|---|---|---|
| 闭集身份分类 | 这段 EEG 属于已注册的 N 个人中的哪一个 | 测试受试者通常出现在训练集中 | Accuracy、Macro-F1、Top-k |
| 闭集验证 | 这段 EEG 是否属于声称的用户 | 每个人要有注册样本和探针样本 | FAR、FRR、EER、ROC-AUC |
| 开集验证 | 是否属于已注册用户；陌生用户必须拒绝 | 测试中包含未注册用户作为冒充者 | EER、FAR@FRR、TAR@FAR |
| 跨条件识别 | 跨天、跨设备、跨任务是否仍能识别 | 训练和测试必须来自不同会话或任务 | 上述指标及性能下降幅度 |

开始前必须向主办方确认：

1. 最终提交的是闭集标签，还是接受/拒绝判断。
2. 测试用户是否在训练集中出现。
3. 测试阶段是否跨会话、跨日期、跨任务或跨设备。
4. 每个用户允许使用多少条注册样本。
5. 是否允许使用公开数据做预训练。
6. 评价发生在单段 EEG、单个 trial，还是连续数据流。

如果这些信息没有确认，先做“固定受试者、划分 trial”的闭集基线，同时保留 subject、session、task、recording 四类元数据，后面才能改成正确协议。

## 2. 两个参考仓库的真实定位

### 2.1 BrainprintNet

仓库：<https://github.com/hustmx721/BrainprintNet>

可用价值：

- 有 BrainprintNet、EEGNet、DeepConvNet、ShallowConvNet、Conformer、FBCNet 等多个 PyTorch 模型。
- 有跨会话、跨任务实验入口。
- 有论文中的多尺度时域卷积、滤波器组、跨频带空间融合思路。
- 有训练、早停、多个随机种子和结果汇总的基础框架。
- MIT 许可证，学习和改造相对方便。

不能直接忽略的问题：

- 仓库不包含原始公开数据，也不包含 README 所说的全部处理结果。
- 它读取的是已经整理好的 `.mat` 或 `.pkl`，不是直接把 PhysioNet EDF 扔进去。需要为你们的数据写适配器。
- `001` 数据集要求类似 `data/mydata/ori_001.mat`，键名为 `ori_train_x`、`ori_train_s` 等；不能按 README 命令直接跑原始 EDF。
- CLI 默认模型名和模型注册表不完全一致。实际训练要显式写 `--model BrainprintNet` 或 `--model EEGNet`，并在正式训练前做一次小样本 smoke test。
- `resolve_device()` 只识别 CUDA 或 CPU，不会使用 Apple MPS。
- 当前 EER 实现基于分类硬标签，不适合作为真实开集验证指标。认证实验必须直接使用 embedding 相似度分数计算 EER。
- 它随机从训练池切验证集。如果你们在切分前就按重叠窗口扩增，滑动窗口会同时出现在训练和验证中，导致虚高。

因此，BrainprintNet 最适合作为：

- 你们的最终深度模型候选。
- 跨会话和跨任务的对照方法。
- 论文复现和消融实验对象。

不适合作为第一天的起点。

### 2.2 EEG-Authentication-System

仓库：<https://github.com/mohamedkhaled110/EEG-Authentication-System>

可用价值：

- 使用 PhysioNet EEGMMIDB，数据最容易获得。
- 展示了 EDF 读取、3 通道选择、窗口切分、CNN、embedding 和 Streamlit 演示的完整雏形。
- 适合快速建立一个能展示的 demo。

必须谨慎的地方：

- 它主要使用 `SxxxR01.edf`，也就是每个受试者的一次 run，不能证明跨会话泛化。
- README 的 99% 左右结果属于闭集身份分类或同数据条件下的演示，不等价于真实身份认证。
- Notebook 以 1 至 89 号受试者训练，测试段落又使用 90 至 109 号受试者的新编号，训练与评估口径和 README 的“109 人”描述并不完全一致。
- 使用长度 160、步长 4 的重叠窗口，相邻样本几乎相同。之后再做随机验证集切分，会高估验证准确率。
- 每个 EDF 文件单独做 Min-Max 归一化，可能改变跨会话可比性。不能不加验证地照搬到正式方案。
- 它是优秀的演示和代码阅读材料，不是严格的比赛评价基准。

结论：学习其“数据读取和界面”，不要直接引用其准确率作为你们的核心结果。

## 3. 推荐的技术路线

### 3.1 总体架构

```text
原始 EDF/BDF/SET
    -> 通道、采样率、事件检查
    -> 带通、陷波、重采样、参考、伪迹处理
    -> trial/固定窗口切分
    -> subject/session/task 分组数据集
    -> 经典特征基线
    -> EEGNet 闭集分类
    -> embedding + 注册/验证
    -> BrainprintNet 和跨会话实验
    -> 误差分析、消融、系统演示
```

### 3.2 四层基线

必须逐层建立，不要跳过前一层。

1. 随机基线和多数类基线。
2. 经典特征基线：分频带功率、Hjorth 参数、协方差、连接性，再配 Logistic Regression 或 SVM。
3. 小型深度基线：EEGNet。
4. 复杂模型：BrainprintNet、FBCNet、Conformer，或你们自己的改进。

经典基线看起来普通，但能最早暴露数据泄漏、标签错误、事件解析错误和切分错误。它通常也是答辩时最有说服力的最低要求。

## 4. 数据来源与选择顺序

### 4.1 第一条主线：PhysioNet EEGMMIDB

数据页：<https://physionet.org/content/eegmmidb/1.0.0/>

文件页：<https://physionet.org/files/eegmmidb/1.0.0/>

数据集基本情况：

- 109 名受试者。
- 64 导 EEG。
- 160 Hz 采样率。
- 每人 14 个 run。
- 前两个 run 为睁眼/闭眼基线，后 12 个 run 为真实运动或运动想象任务。
- EDF+ 中包含 T0、T1、T2 事件。
- 许可证为 Open Data Commons Attribution License v1.0。
- 整包 zip 约 2 GB，解压后更大。

官方下载方式：

```bash
aws s3 sync --no-sign-request \
  s3://physionet-open/eegmmidb/1.0.0/ \
  data/raw/eegmmidb
```

如果只想先试一个文件：

```bash
mkdir -p data/raw/eegmmidb/S001
curl -L \
  https://physionet.org/files/eegmmidb/1.0.0/S001/S001R01.edf \
  -o data/raw/eegmmidb/S001/S001R01.edf
```

建议第一周先下载 10 个受试者，不要立刻搬全量数据。

### 4.2 第二条主线：M3CV

Kaggle 数据页：<https://www.kaggle.com/competitions/eeg-biometric-competition/data>

M3CV 包含多受试者、多会话、多任务条件，和 BrainprintNet 论文的目标更一致。下载可能需要 Kaggle 登录、接受比赛规则并配置 API Token。

### 4.3 第三条主线：OpenBMI

## 5. GitHub 和 Git 入门

### 5.1 GitHub 是什么

GitHub 是代码托管和协作平台，不是主要的数据网盘。一个仓库通常包含：

- `README.md`：项目说明、安装方法、数据说明、结果。
- `requirements.txt` 或 `environment.yml`：依赖。
- `src/`：源代码。
- `scripts/`：数据处理和训练入口。
- `configs/`：实验配置。
- `LICENSE`：许可证。
- Issues：问题讨论。
- Releases：稳定版本和预训练权重。

### 5.2 判断一个仓库是否值得参考

按以下顺序检查：

1. README 是否说明数据从哪里下载、如何预处理、如何训练、如何复现结果。
2. 最近一次提交和 Issue 是否活跃。
3. 是否提供训练脚本，而不是只有模型定义或界面。
4. 是否提供明确的 train/validation/test 划分。
5. 报告的是闭集分类还是开集验证。
6. 是否混用了重叠窗口。
7. 许可证是否允许你们使用和修改。
8. 是否把数据集和大模型提交进仓库，导致克隆非常慢。

不要只看 Star 数。高星项目也可能只是界面漂亮，低星项目也可能有严谨的数据处理。

### 5.3 GitHub 搜索语法

```text
"EEG brainprint" in:name,description,readme language:Python
"EEG authentication" in:name,description,readme language:Python
topic:eeg topic:deep-learning
"EEG biometric" stars:>5

```

在仓库内搜索文件：

```text

```

### 5.4 必会 Git 命令

安装 Git 后先配置：

```bash

```

克隆仓库：


日常操作：


查看历史：

```bash

```

不要用 `git add .` 把数据、缓存、模型权重和 IDE 配置一起提交。仓库根目录先放：

## 8. 数据检查与统一样式

### 8.1 第一份 EDF 要检查什么

```python
import mne

path = "data/raw/eegmmidb/S001/S001R01.edf"
raw = mne.io.read_raw_edf(path, preload=True)

print(raw)
print(raw.info)
print(raw.ch_names)
print(raw.annotations)
print(raw.times[-1])

raw.compute_psd(fmax=80).plot()
raw.plot(duration=10, n_channels=20)
```

检查内容：

- 通道数量和名称是否和论文、事件说明一致。
- 采样率、时长、单位是否正确。
- 有无 NaN、全零通道、平线、饱和和异常幅值。
- 有无 50 Hz 或 60 Hz 工频噪声。
- 事件码 T0、T1、T2 的含义是否随 run 类型变化。
- 每个受试者、每个 run、每类事件的样本数是否完整。
- 文件名中的受试者编号和内部标签是否一致。

### 8.2 建立统一数据字典

不要只保存 `X` 和 `y`。每个样本至少保留：

```text
sample_id
subject_id
session_id
task_id
run_id
recording_id
window_start
window_end
label
split
source_file
```

推荐内部格式：

```text
X: float32, shape = [N, C, T] 或 [N, 1, C, T]
y: int64, shape = [N]
metadata: CSV 或 Parquet
```

`C` 是通道数，`T` 是时间点数，`N` 是样本数。不要在不同实验里悄悄改变维度顺序。

### 8.3 建议的初步探索指标

- 每人、每会话、每任务的 trial 数。
- 每个 channel 的均值、标准差、峰峰值和缺失率。
- PSD 图，以及 alpha、beta 频带能量分布。
- 事件间隔、trial 持续时间、伪迹比例。
- 原始波形、平均 ERP、通道相关矩阵。
- 同类样本距离和跨会话样本距离。

UMAP 或 t-SNE 只能用来看趋势，不能替代严格的留出测试，也不能根据测试集图反复调参。

## 9. 预处理规范

### 9.1 推荐默认流程

先固定一套简单流程，再逐项消融：

1. 读取 EDF/BDF，确认单位和通道类型。
2. 统一通道名称，设置标准 10-20/10-10 montage。
3. 工频陷波，例如 50 Hz。
4. 带通滤波：
   - 通用基线：1 至 45 Hz。
   - 复现 BrainprintNet：8 至 32 Hz，但要做对照，不要直接假定最优。
5. 统一重采样，例如 160、200 或 250 Hz。
6. 可选共同平均参考 CAR。
7. 根据事件截取 trial 或切成固定窗口。
8. 幅值异常拒绝、坏道检测；ICA 放在第二阶段，不要第一天就全量使用。
9. 按 trial 做零均值、单位方差，或使用只在训练集拟合的标准化器。

所有预处理参数必须写进配置文件。测试数据不能参与拟合任何归一化、PCA、CSP 或对齐参数。

### 9.2 窗口设计

- 训练可使用 2 秒窗口，50% 重叠以增加样本。
- 验证和测试优先使用不重叠窗口。
- 同一个 trial 的多个窗口不能跨 train/test 划分。
- 最终应把同一 trial 的窗口分数聚合成一个 trial 分数，例如取平均或中位数。
- 报告样本数时，同时报告窗口数和独立 trial 数。

### 9.3 伪迹处理

第一阶段只做温和处理：

- 剔除明显超出量程或全零通道。
- 拒绝峰峰值过大的窗口。
- 检查眼电、肌电和运动伪迹集中的时段。

第二阶段再做：

- ICA 去除眨眼、眼动和心电成分。
- 坏道插值。
- Euclidean Alignment 或 Centroid Alignment。
- 数据增强。

过度清理可能同时删除个体特征。每次加入一种处理，都要做同切分对照实验。

## 10. 数据切分：本项目最容易出错的地方

### 10.1 绝对不能犯的错误

```text
先把连续 EEG 切成重叠窗口
-> 全局随机打乱
-> 随机分训练和验证
```

相邻窗口高度重叠，验证集会出现训练样本的近似副本，准确率会虚高。

同样不能：

- 用同一条 recording 的窗口同时训练和测试。
- 用同一 session 的 trial 同时做注册和探针。
- 把“见过这个人的其他 trial”说成“未见用户”。
- 在测试集上选阈值、选 epoch 或选模型后再报告结果。

### 10.2 推荐的四套协议

| 协议 | 训练 | 测试 | 回答的问题 |
|---|---|---|---|
| Within-session | 同一会话的部分 trial | 同一会话的其他 trial | 基础可分性 |
| Cross-session | 会话 A | 会话 B | 跨天是否有用 |
| Cross-task | 任务 A | 任务 B | 任务迁移能力 |
| Open-set verification | 已知用户的注册集 | 已知用户探针 + 未注册冒充者 | 能否安全认证 |

最严格的做法是按 `recording_id` 或 `trial_id` 分组，使用 `GroupKFold`、`GroupShuffleSplit`，而不是普通 `train_test_split`。

### 10.3 认证实验的注册和探针

对每个用户：

1. 从训练/注册会话中取 5、10 或 20 条样本。
2. 提取 embedding，计算平均模板。
3. 用另一个会话或完全不重叠的 trial 做探针。
4. 计算探针与模板的余弦相似度。
5. 在 validation 上选阈值。
6. 在测试集上一次性评估。
7. 对未知用户，只允许作为冒充者，不加入注册模板。

必须报告注册样本数。5-shot、10-shot、20-shot 的难度完全不同。

## 11. 模型训练步骤

### 11.1 第一步：经典特征基线

对每个通道计算：

- Delta：1 至 4 Hz。
- Theta：4 至 8 Hz。
- Alpha：8 至 13 Hz。
- Beta：13 至 30 Hz。
- Gamma：30 至 45 Hz。

特征可以包括：

- 绝对带功率。
- 相对带功率。
- 对数功率。
- 谱熵。
- Hjorth activity、mobility、complexity。
- 通道间相干性或相位滞后指数。
- 空间协方差。

分类器先用 Logistic Regression、线性 SVM 或 Random Forest。每个参与者在训练集中应有相同数量的 trial，避免分类器偏向某个人。

这一步的目标不是拿冠军，而是得到一个可信的最低准确率。

### 11.2 第二步：EEGNet 闭集分类

输入建议：

```text
[batch, 1, channels, time]
```

训练起点：

- 交叉熵损失。
- AdamW。
- 学习率 1e-3 或 3e-4。
- Batch size 16、32 或 64。
- 100 至 300 epoch，早停。
- 余弦退火或 ReduceLROnPlateau。
- 梯度裁剪。
- 类别平衡采样。
- 5 个随机种子，报告均值 ± 标准差。

使用全部 64 通道作为主实验。3 通道版本只适合快速调试或低通道演示，不能代表完整空间信息。

### 11.3 第三步：从分类模型变成身份 embedding

在分类头之前取特征，例如 128 维或 256 维，做 L2 归一化。训练方式可选择：

- 普通交叉熵。
- Center Loss。
- Triplet Loss。
- ArcFace 或 CosFace。
- 交叉熵 + 对比损失。

认证时建议使用余弦相似度：

```text
template_u = normalize(mean(embedding(enrollment_u)))
score(x, u) = cosine(embedding(x), template_u)
accept if score >= threshold
```

不要把 softmax 最大概率直接当成“认证置信度”，除非你们专门做了校准。

### 11.4 第四步：BrainprintNet

等 EEGNet 基线稳定后，再把 PhysioNet 或比赛数据转换到 BrainprintNet 需要的格式。

建议顺序：

1. 写 `prepare_brainprint_data.py`。
2. 先转换 10 个受试者。
3. 只训练 1 个 epoch 做 smoke test。
4. 检查输入 shape、标签范围、类别数、损失是否可以下降。
5. 再扩展到全量数据。

正式命令必须显式指定模型，例如：

```bash
python -m src \
  --mode baseline \
  --dataset 001 \
  --model BrainprintNet \
  --data-root /path/to/prepared/data \
  --output-root outputs \
  --batch-size 16 \
  --epochs 3 \
  --seeds 2026
```

第一次只跑 3 个 epoch 和 1 个 seed。确认输出、日志和 checkpoint 正确后，再开 5 个 seed 的长训练。

### 11.5 数据增强

可使用：

- 小幅高斯噪声。
- 随机时间平移。
- 随机时间裁剪。
- 幅度缩放。
- 通道 dropout。
- 频率遮挡。
- 通道混合。

谨慎使用：

- 时间反转。
- 大幅 mixup。
- 过度滤波。
- 直接复制相邻重叠窗口。

增强策略要在训练集内部完成，不能用测试集做增强后再求平均。

## 13. 研发中最容易出现的坑

1. **准确率虚高**：重叠窗口随机切分、同 session 混合。
2. **把分类当认证**：模型能区分 109 人，不代表能拒绝陌生人。
3. **未知用户泄漏**：测试用户其实已经参与训练。
4. **测试调参**：反复看测试集，最终报告结果不再独立。
5. **会话漂移**：跨天电极位置、阻抗、疲劳、咖啡因、睡眠都会改变信号。
6. **伪迹身份化**：模型可能识别的是眼动、肌电、设备或采集顺序。
7. **任务泄漏**：跨任务实验里把目标任务的测试数据混入训练。
8. **归一化泄漏**：用全体样本拟合 scaler、PCA、协方差参考。
9. **标签错误**：文件名编号、事件码含义、零基/一基编号不一致。
10. **类别不平衡**：某人文件缺失，分类器仍把缺失索引当成一个有效类别。
11. **数据版本变化**：同文件名不同下载批次的采样率、通道或事件不一致。
12. **只报告一个种子**：结论可能是随机波动。
13. **只看平均指标**：少数用户可能错误率极高，必须看分人结果。
14. **照搬论文超参数**：通道数、采样率、窗口长度不同，参数不可直接复制。
15. **把 GitHub 当数据盘**：原始 EEG 和模型权重不应提交到普通 Git。
16. **缺少失败案例**：答辩时需要说明在哪些会话、任务、用户上失败。

## 17. 比赛成果建议

一个可信的比赛成果至少应包含：

1. 数据集和预处理示意图。
2. 明确的闭集/开集、跨会话/跨任务协议。
3. 经典基线和深度基线。
4. 多个随机种子的均值和标准差。
5. 开集认证的 EER、FAR、FRR、ROC。
6. 分人误差分析和失败案例。
7. 频带、通道、参考、增强和损失的消融。
8. 一个可操作的注册与认证演示。
9. 推理延迟和资源消耗。
10. 可复现的配置、日志、模型卡和许可证说明。

如果比赛强调创新，优先考虑以下方向：

- 跨会话鲁棒性，而不是在同会话里继续提高 0.5% 准确率。
- 小样本注册，比较 5-shot、10-shot、20-shot。
- 未知用户拒绝和阈值校准。
- 任务无关的身份 embedding。
- 频带和通道可解释性。
- 模型压缩和边缘设备推理。
- 抗重放/活体检测，但要明确它是额外的安全问题，不能只靠身份分类器。

## 19. 核心术语

| 术语 | 含义 |
|---|---|
| EEG | 脑电图，多通道时间序列 |
| Brainprint | 用 EEG 中相对稳定的个体特征进行身份识别 |
| Trial | 一次任务刺激或一段固定实验记录 |
| Epoch | 按事件截取的一段时间窗 |
| Session | 一次独立实验会话，通常对应同一天或同一佩戴过程 |
| Closed-set | 测试者一定属于已注册用户 |
| Open-set | 测试中可能出现未注册用户，必须拒绝 |
| Enrollment | 注册阶段，保存用户模板 |
| Probe | 认证阶段用于比对的探针样本 |
| Template | 多条注册 embedding 的平均或原型 |
| EER | FAR 与 FRR 相等时的错误率 |
| FAR | 冒充者被错误接受的比例 |
| FRR | 真实用户被错误拒绝的比例 |
| Data leakage | 测试信息以某种方式进入训练或调参 |
| Domain shift | 跨天、跨设备、跨任务导致的分布变化 |
